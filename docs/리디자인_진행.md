기준 문서: `GUILD_ARCHIVE_RPG_UIUX_명세서` (업로드 docx)

## 저장소 구조 요약
- 빌드 없음, 정적 파일을 GitHub Pages로 배포 (상대 경로 사용)
- `index.html`: CSS(약 2,000줄) + 마크업 + 인라인 JS 단일 파일
- `calendar.js`(캘린더/월드맵 테마), `social.js`(로그인·랭킹), `service-worker.js`(오프라인 캐시)
- 저장: `localStorage['quest-planner-state']` 단일 JSON + `qp_*` 보조 키, JSON 백업/복원 지원
- 서버(`server/`): Express + MongoDB, 로그인 시 퀘스트·점수만 동기화

## 위험 요소
- 단일 파일에 CSS·JS가 섞여 있고, JS 템플릿 안에 인라인 스타일·하드코딩 색상이 많음 → 토큰만으로 전부 바뀌지 않음
- 서비스워커 캐시: CSS 변경 시 `CACHE_NAME` 버전을 올려야 기존 사용자에게 반영됨
- 외부 폰트(Pretendard, Noto Serif KR) 실패 시 시스템 폰트로 대체됨

## 아이콘 리소스 적용 (1차)
- 출처: 사용자 제공 `아이콘 & 이미지 리소스 가이드` 이미지에서 잘라낸 일러스트
- 배경(녹색 계열 어두운 색)을 가장자리부터 제거해 투명 PNG(96×96, 화면 28px 표시)로 저장: `icons/ui/nav-*.png`
- 하단 내비 5개 이모지 → 아이콘 교체 (일기=모험일지 책, 캘린더=날짜 퀘스트, 홈, 월드맵=탐험 지도, 상점). 메뉴 구성·동작은 그대로
- 비활성은 채도를 낮추고 활성만 원색 + 상단 막대로 표시, 일기 미작성 알림 점은 원색 유지
- 예비 추출: `quest`, `equip`, `more` (현재 미사용)
- 서비스워커 캐시 v14, 아이콘 파일 사전 캐시 추가
- 한계: 원본이 합성 이미지라 해상도가 약 70px 수준 → 3배 이상 확대 시 흐려짐. 원본 개별 PNG/SVG가 있으면 교체 권장

## 아이콘 리소스 적용 (2차, 전체)
- 리소스 가이드 이미지의 섹션별 아이콘을 자동 분할해 투명 PNG 69종으로 저장 (`icons/ui/<분류>-<이름>.png`, 128색 압축, 총 약 400KB)
  - 분류: quest, char, equip, shop, misc, status, diff, stat, grade, item, vis, nav
  - 제외: 업데이트·비동기 아이콘(가는 선 그림이라 배경 제거 후 형태가 깨짐), 직업 초상화(명세 5.3: 기존 캐릭터 아트 유지)
- `EmojiIcons`(index.html): `EMOJI_ICON_MAP` 하나로 화면의 이모지를 아이콘으로 바꿔 그린다
  - 데이터·문구 원본은 그대로, DOM 표시만 교체 (img alt에 원래 이모지 보존)
  - 사용자가 쓴 글(퀘스트 제목·일기·채팅·닉네임)과 입력창은 제외
  - 알림(Notification)·alert 등 DOM 밖 문구는 이모지 그대로
- 아이콘 파일은 서비스워커의 이미지 런타임 캐시로 저장됨

## 2단계: 홈 / 퀘스트 (완료)
- 홈: 캐릭터·칭호 + 오늘 요약(오늘 완료 / 오늘 획득 XP / 보유 골드) + 진행도·출석을 하나의 패널로 통합
  - 요약 값은 실제 데이터만 사용: 완료 수=오늘의 퀘스트, 획득 XP=`weekLog` 오늘 항목, 골드=`state.gold`
- 오늘의 의뢰: 남은 의뢰 먼저, 최대 5개 표시 + `전체 의뢰 보기 (+N)`
- 퀘스트 행: 카드 나열 → 한 패널 안의 구분선 행
  - 완료 버튼을 `<button>`으로 바꿔 키보드 조작 가능, 터치 영역 48px, aria-label/aria-pressed 제공
  - 완료 상태를 체크 + `완료` 글자 + 취소선으로 표시 (색에만 의존하지 않음)
  - 유형(일일/일회성/날짜지정)·난이도 아이콘, 보상은 장비 보너스를 반영한 예상값과 단위(XP, G) 표시
- 빈 상태: 안내 문구 + `첫 의뢰 등록` 버튼 (추가 시트 열림)
- 전체 의뢰 화면: 분류 필터를 한 줄 가로 스크롤로 변경, 기존 분류·동작 유지

## 3단계: 장비 / 상점 / 암시장 (완료)
- 진열대(상점·암시장 공용 `shopItemRowHTML`): 2열 카드 → 한 열 장부 행
  - 아이콘 → 이름·상태(장착 중/보유) → 효과 → 현재 장비 대비 비교(▲/▼ %p) → 가격
  - 구매 버튼에 가격 표시, 아래에 `구매 후 잔액` 또는 `N G 더 필요`
  - 비교 수치는 아이템의 실제 효과 값(xpBonus·goldBonus·duelBonus)만 사용
  - 아이템에 등급 데이터가 없어 등급은 표시하지 않음 (임의 생성 금지)
- 장비 슬롯: 장착=실선 브론즈 테두리+`장착 중`, 빈 슬롯/미보유=점선+글자. 장비 선택 목록에도 비교 표시
- 상태 메시지 통일: `toast(msg, kind)`에 성공/오류 스타일 추가 (기존 호출은 그대로 동작)
  - 구매 완료(잔액 포함)·장착 완료=성공, 골드 부족·보유 장비 없음=오류, 결투 승패 구분
- 암시장: 적갈색·먹색 전용 테마, 탭 3개(비밀 상점/결투장/미니게임) 유지
  - 결투 시작 전: 보유 골드·베팅 범위·남은 결투(하루 1회)·선택 시 승패별 예상 증감
  - 미니게임 목록: 게임 상수에서 계산한 베팅 범위·보상 배율, 보유 골드
  - 결과: 승패 + 골드 증감(+/−) + 현재 잔액 (결투는 저장된 결과와 배율로 계산, 미니게임은 시작 시점 잔액과 비교 — 표시 전용, 저장 안 함)
- 경제 규칙(가격·배율·확률·하루 횟수·폐업 한도) 변경 없음

## 4단계: 일기 / 탐험 / 통계 / 설정 (완료)
- `saveState()`가 저장 성공 여부(true/false)를 반환하도록 변경. 기존 호출부는 반환값을 쓰지 않아 동작 동일
- 일기 (5.6)
  - 모험일지 안에 `기록 쓰기` / `나의 기록 N` 탭으로 쓰기와 목록 분리. 수정·작성 진입 시 자동으로 쓰기 탭
  - 저장 버튼: `저장 중…` → `✓ 저장 완료` / `저장 실패 · 다시 저장`. 실제 저장이 실패하면 완료 메시지를 띄우지 않음 (이전에는 저장 실패도 완료로 표시됐음)
  - 삭제는 기존 확인창 유지, 삭제 저장 실패 시 오류 알림
- 탐험 (5.7)
  - 지도 높이 240px → 화면 높이의 52%(260~420px)
  - 상태 표시줄(아이콘+글자): 위치 확인 중 / 위치 수신 중 / 측정 중 / 저장 완료 / 저장 실패 / GPS 신호 약함 / 권한 거부 / 위치 오류 / 미지원
  - 산책 시작(브론즈 버튼 ▶)과 종료(빨간 테두리 버튼 ■)를 다른 모양으로, 종료 전 확인창(현재 거리 안내)
  - 거리 계산·GPS 필터 로직은 변경 없음
- 통계·업적 (5.8)
  - 이번 주 리포트에 최근 7일 막대 그래프: 완료 수/획득 XP 전환, 단위 표기, 최댓값·오늘만 값 라벨, 막대 탭/호버 시 값 표시, `표로 보기`, 합계·평균·최다일 해석 문장
  - 기간 선택은 넣지 않음: 저장 데이터(`weekLog`)가 최근 7일만 보관하기 때문 (데이터 구조 변경 금지)
  - 업적 상세: `조건 · …` / 달성 상태 / `보상 · …`을 줄로 분리
  - 캐릭터 화면 아바타의 발광 효과 제거
- 설정 (5.8, 7)
  - 아코디언 제목을 키보드(Tab, Enter/Space)로 열고 닫기, aria-expanded 제공
  - 위험 구역 카드 강조, 회귀 확인 버튼을 `취소` / `회귀하기`로, 기존 문구는 유지하고 "골드·장비·일기도 초기화, 먼저 백업 권장" 안내 추가
  - 회귀 확인창: 기본 포커스는 `취소`, Esc로 닫기, 닫으면 원래 버튼으로 포커스 복귀
